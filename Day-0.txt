What is Repository?
-> repository is where G tracks everything in your project think of it like a folder that stores all the versions of your code simply put if a folder is being tracked by git we call it a repo.

Staging - ready to commit

Git - It is a tool to track changes
Github - It is a cloud platform that allows you to store git repo online and collaborate with others to push the local projects to github where we have to link out repo to remote

There are two types of repository: 
1. local : the version of a project that exist on own machine.
in case of "git init"  we initialise a repo in local folder changes they are private until we push it into remote repo
2. remote : the version of a project stored on a server like github, gitlab, bid bucket etc, it used to share code between collaborators and keep project versions in sync across different users computers.

Everyone have their own local repo and a common remote repo where they sync their local repo.
When we clone a repository from GitHub git automatically names the remote repository as origin by default it's basically an alias for the remote repositories URL
repository origin = url

step 1 : create a new repo at github
step 2 : change the name master to main --> git branch -M main
step 3 : link local repo to remote repo --> git remote add origin <paste repo rigin url>
step 4 : push local commit to remote repo--> git push -u origin main.     (here "origin" refer to full url, instead to typing full url we use "origin")

    4 commits c1 -> c2 -> c3 -> c4, reset to 2nd (head on 2nd) and do some changes 

    SOFT RESET.  = git reset --soft <commit-hash>

    git reset --soft only moves your local branch pointer backward,
    all the code from your subsequent commits went into the staging area. 
    When you made your new edits and ran git add ., those new changes were added 
    right alongside them. Your staging area now contains a mix of the old afterward 
    changes and your fresh edits.
    When you run git commit -m "..." now, Git takes everything currently sitting in 
    that staging area and bundles it into one single, brand-new commit.

    c3 -> c4 are automatically staged, new c2 is unstaged
    stage newc2 and commit

    MIXED RESET = DEFULT WALA = git reset <commit-hash>
    In the case of a mixed reset (--mixed), Git empties the staging area entirely.
    Here is where everything goes:
    The Undone Commits (3rd and 4th): Their changes are left in your working directory as unstaged modifications.
    Your New Edits (in the 2nd commit files): They are also sitting right there in your working directory as unstaged changes alongside everything else.
    Because everything is unstaged, you have to manually stage whatever you want to include before you can commit again.
    To bundle everything together into a new single commit, you would run:
    
    git add .
    git commit -m "Your new commit message"

    HARD RESET == git reset --hard <commit-hash> 
    When you run git reset --hard <commit-hash> (for example, resetting back to the 2nd commit):
    Commit Pointer Moves: Your branch (HEAD) moves back to the target commit (2nd commit).
    Staging Area Cleared: All staged changes from the 3rd and 4th commits are completely wiped out.
    Working Directory Cleared: All file modifications, unstaged edits, and newly added tracked files are discarded from your local disk.

    // SENARIO 2
    When you merged your dev-rishi branch into main via the GitHub web interface, GitHub created a merge commit directly on the 
    remote main branch. Because that merge happened in the cloud, your local main branch on your laptop doesn't know about it 
    yet—which is why your local branch was "behind" and threw that non-fast-forward error when you tried to push.

    note : what is non-fast-forward error?
    This non-fast-forward error means that the remote main branch on GitHub has commits that your local computer doesn't have yet.

    To bring those remote merge commits down to your local computer and align your local main with GitHub, 
    run the merge pull command 
    git pull origin main --no-rebase
